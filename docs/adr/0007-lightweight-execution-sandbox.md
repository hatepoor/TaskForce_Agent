# 执行沙箱:接入用户自建的远程 Docker 沙箱服务

执行智能体需要真实执行能力(运行代码、读写文件、执行 Skill 附带脚本)。用户已自建基于 Docker 的沙箱服务并部署于其远程服务器,因此本仓库**不开发沙箱本身,只实现本机侧接入**:`tools/sandbox/client.py` 将沙箱能力适配封装为 LangChain 工具 `execute_python(code)`,调用时携带 `session_id`(取会话线程 id),若沙箱支持会话级工作区,则同一会话内"先写文件、下一步再读"的跨步任务可用;具体接口协议与容器策略以沙箱实际实现为准。整体形态为**控制面在本地、执行面在远程服务器**,容器级隔离。曾考虑的轻量本地子进程方案(Windows 上资源限制不可靠、与本机文件系统无隔离)被否决。接入要求:沙箱端点必须鉴权(它是"任意代码执行"端点,绝不裸奔公网),`.env` 配 `SANDBOX_URL` / `SANDBOX_API_KEY`。
