## 0. 设计原则与后端契约速查

### 0.1 三条设计原则

1. **工具,不是产品**。没有引导页、没有 mascot、没有庆祝动画、没有空状态插画。界面存在的意义是让"智能体正在干什么"和"我还能管什么"这两件事一眼可见。
2. **信息密度优先于留白**。单用户工具不需要靠大间距撑气场。对话正文 14px/1.7,外壳 13px,元信息 12px,角标 11px。
3. **状态靠克制的方式表达**。用一条 12px 的字、一个 6px 的圆点、一条 2px 的左边框区分状态;**不用色块、不用徽章海洋、不做位移动画**。整个界面只有一个强调色。

### 0.2 后端契约速查

**SSE 事件格式**:每帧 `data: {"<类型>": <载荷>}\n\n`,**单键对象,无 `event:` 行**,前端按键名分发。JSON 为 `ensure_ascii=False`(中文直出)。字段级契约以 API-CONTRACT.md 为唯一事实源,此处仅列 UI 相关要点:

| SSE 事件 | 负载要点 | 前端动作 |
|---|---|---|
| `token` | 增量字符串 | 追加到当前轮正文末尾(字符串累加,非 replace) |
| `route` | `{next, question, tasks[]}`,`next ∈ answer\|ask\|memory\|dispatch` | 轨迹条累加一条记录 |
| `interrupt` | **对象信封** `{kind: "ask"\|"memory"\|"unknown", text}`(B3 后) | 按 kind 判别卡片类型并挂起输入 |
| `usage` | `{thread_id, calls, input_tokens, output_tokens}`,**进程级累计** | 差分后展示本轮增量角标 |
| `error` | `{message, code?}`(B4 后) | 错误条;`code: "recursion_limit"` 按正常回复样式呈现 |

**关键事实**:① B4 前**没有 `done` / `error` 帧**,读流结束即本轮结束,`completed` vs `broken` 靠客户端判定;② `route` 只含路由决策,**不含子智能体 ResultSummary**;③ `usage` 是进程累计值;④ `POST /chat` 需带 body,**不能用 `EventSource`**,须 `fetch` + `ReadableStream` 手工解析。

**子智能体身份色**(轨迹/摘要里唯一允许出现的彩色):

| agent | 中文名 | 色(深色模式) |
|---|---|---|
| `retriever` | 知识库检索 | 蓝 `#5b9dff` |
| `research` | 联网调研 | 紫 `#a98bff` |
| `executor` | 沙箱执行 | 琥珀 `#e0a552` |
