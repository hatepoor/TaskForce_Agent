## 五、验收标准(可勾选的自测清单)

**环境自检**(2026-09-20 已在本机执行, 结论见本节末尾; PDF 相关项需真实 PDF 才能验):

- [ ] `uv run python -c "from docling.datamodel.base_models import InputFormat; print([f.value for f in InputFormat])"` → 含 pdf / docx / md, 确认 md 输入支持与枚举拼写
- [ ] `uv run python -c "from docling_core.types.doc import DocItemLabel, ContentLayer, PictureItem; print([l.name for l in DocItemLabel]); print([c.name for c in ContentLayer]); print([m for m in dir(PictureItem) if 'image' in m.lower()])"` → 定稿 4.3 的枚举与取图入口
- [ ] `uv run python -c "import inspect; from docling.document_converter import DocumentConverter; print(inspect.signature(DocumentConverter.__init__))"` → 确认 `allowed_formats` 是否存在
- [ ] `uv run python -c "from docling.datamodel.base_models import ConversionStatus; print(list(ConversionStatus))"` → 定稿失败分支的写法
- [ ] `uv run python -c "import docling.datamodel.pipeline_options as p; print([n for n in dir(p) if 'Ocr' in n])"` → 列 OCR 选项类名
- [ ] 三类最小样例(1 页含表格+图片的 pdf / 含多级标题与合并单元格表的 docx / 含表格的 md)各 `convert()` 一次, 打印 `[(i.label, getattr(i,'level',None), i.prov[0].page_no if i.prov else None) for i,_ in doc.iterate_items()]`
- [ ] 用带页眉的 pdf 核对 `doc.furniture` 与遍历结果的差集, 定稿"规则 A + 规则 B"的覆盖关系
- [ ] 观察合并单元格表 `export_to_markdown()` 的摊平结果, 记录是否可接受
- [ ] GBK 编码的 `.md` 读一次, 确认是否需要编码兜底(先探测编码读成字符串, 必要时写 UTF-8 临时副本)

**实测结论(2026-09-20, docling 2.128.0 / 本机)**:

- `InputFormat` 含 pdf/docx/md(枚举值比预期宽, 还含 doc/pptx/html/xlsx 等——仍只放行三种后缀);
- `DocumentConverter.__init__` **有** `allowed_formats` 参数; `ConversionStatus` = PENDING / STARTED / FAILURE / SUCCESS / PARTIAL_SUCCESS / SKIPPED;
- 标题: `SectionHeaderItem.level` 是直接字段; `TitleItem` 无 level → 约定记 **0**;
- 表格: `TableItem.export_to_markdown(doc)` 可用, 且**已自行处理**单元格内换行(`\n`→空格)与竖线(`|`→`&#124;`); 兜底数据可取 `item.data.grid`(cell 有 `text/row_span/col_span/start_row_offset_idx`);
- 图片: `PictureItem.get_image(doc)` 返回 PIL 图像(docx 下无需 `generate_picture_images`; PDF 仍保留该开关);
- md/docx 的 `prov` 为空 → `page_no=None`; 两者的 `doc.furniture.children` 均为 0(这两类后端不产生 furniture 条目);
- `.doc` 不在放行后缀内: 入口按后缀直接给中文报错即可, 无需尝试转换。

**模块落地后**:

- [ ] 三格式各 ≥ 1 样例解析成功: `items` 非空; `type` / `text` / `heading_path` / `page_no` / `level` / `image_path` 六字段齐全; 无空 `text` 的 text/table 条目
- [ ] `heading_path` 与人工目录抽样 5 条一致; pdf 的 `page_no` 与实际页码一致; docx/md 为 `None`
- [ ] 表格: 整块 Markdown(含表头分隔行), 人工抽 3 张核对行列数; 整表只占一个条目, 允许 `char_len` 超 1800
- [ ] 图片: 落盘文件存在且 Pillow 可打开; 占位文本非空且含 `image_path`; `RAG2_IMAGE_DESC=off` 时 monkeypatch 断言 0 次外部调用
- [ ] 构造"逐页重复页眉"样例 pdf: clean 后该文本出现 0 次, 正文未误伤; 剔除清单落 stats
- [ ] 超短行合并: PDF 断行样例合并成完整一句; 标题未被并进正文(`level` / `heading_path` 边界保持)
- [ ] 去重: 相邻重复条目只留一条; 相邻两个不同标题(即使同名)均保留
- [ ] `.doc` 样例得到明确的中文异常提示; 损坏 pdf 不中断整批, 路径与原因进 `IngestReport.failed`
- [ ] 单测(tests/, 全部不依赖真实模型): clean 五条规则各一组输入输出断言(内存构造 `ParsedDoc`); parse 用 monkeypatch 桩掉 converter; `ParsedDoc` 四字段 + `ParsedItem` 六字段完整性断言
- [ ] 首次运行在 `HF_ENDPOINT` 镜像下完成模型下载并解析成功; 之后断网可重复解析(模型已缓存)
