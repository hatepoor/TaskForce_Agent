**执行记录(2026-09-21, 真 Milvus 2.6.0 + 真百炼多模态 embedding)**: 

| 命令 | 结果 |
|---|---|

| `python -m rag_v01.cli delete`(缺 id) | `错误: delete 需要 doc_id(可用 list 查看)` + 退出码 1 |

## 六、与其它模块的依赖关系

包内(全部相对 import,箭头为"依赖"):

```
contracts.py ← config.py ← {parse, clean, chunk, embed, store, retrieve, evaluate, cli}
ingest.py  → parse → clean → chunk → embed → store   (编排 模块 02/03/04)
retrieve.py → store + embed                            (模块 05)
evaluate.py → retrieve + ingest(语料入库)             (模块 06)
__init__.py → ingest / retrieve / evaluate             (facade)
cli.py → __init__ 三入口 + store(运维子命令)
```

与本套文档:本篇是 [00-总览](README.md) 的落地出口;契约字段定义见 [02](README.md)/[03](README.md)/[04](README.md)/[05](README.md),评估入口见 [06](README.md),进度勾选回 [TODO.md](./TODO.md)。

与项目(仅移植期发生,包本身零依赖):`agent/subagents/retriever.py`(kb_search 装配与 _collect_hits)、`api/routers/knowledge.py` 与 `cli/commands/knowledge.py`(RAGStore 等价面)、`settings/db/store.py`(旧 embed 复用点)、tests 七处 monkeypatch 点——均为 4.5/4.6 的替换对象,不构成 rag_0.1 的 import 依赖。
