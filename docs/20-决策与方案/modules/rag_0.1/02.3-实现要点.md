### 4.1 converter 装配(`parse.py`)

```python
# parse.py 骨架(教学说明用, 非完整实现)
from docling.datamodel.base_models import InputFormat
from docling.datamodel.pipeline_options import PdfPipelineOptions, TableFormerMode
from docling.document_converter import DocumentConverter, PdfFormatOption

def build_converter(cfg) -> DocumentConverter:
    p = PdfPipelineOptions()
    p.do_ocr = cfg.do_ocr                          # RAG2_DO_OCR, 默认关(见 §一 边界)
    p.do_table_structure = True
    p.table_structure_options.mode = TableFormerMode.ACCURATE   # 语料量小, 质量优先
    p.images_scale = 2.0                           # 图片素材分辨率
    p.generate_picture_images = True               # 抽图片本体(与整页图是两回事)
    return DocumentConverter(
        format_options={InputFormat.PDF: PdfFormatOption(pipeline_options=p)},
        # allowed_formats=[InputFormat.PDF, InputFormat.DOCX, InputFormat.MD],  # 参数是否存在【待验证】
    )

# 使用: result = converter.convert(path); doc = result.document
# result.status 非 SUCCESS/PARTIAL_SUCCESS 一律按失败处理(4.7 坑位 1)
```

已核实: `format_options={InputFormat.PDF: PdfFormatOption(pipeline_options=...)}` 构造形式、`do_table_structure`、`table_structure_options.mode`(`TableFormerMode.ACCURATE` 即官方默认档)、`images_scale`、`generate_picture_images`(官方 `pictures_description` 示例即用法)。
**待验证**: (a) `DocumentConverter` 是否接受 `allowed_formats` 白名单参数——验证: `uv run python -c "import inspect; from docling.document_converter import DocumentConverter; print(inspect.signature(DocumentConverter.__init__))"`; 保险做法是自己按后缀校验, 不依赖该参数。(b) `ConversionStatus` 成员名——验证: `uv run python -c "from docling.datamodel.base_models import ConversionStatus; print(list(ConversionStatus))"`。

### 4.2 三种格式的解析差异

| 维度 | PDF | DOCX | MD |
|---|---|---|---|
| 解析路径 | 布局模型逐页推理 + TableFormer + 可选 OCR | OOXML 结构直读(规则驱动, 无模型) | Markdown 后端解析(无模型) |
| 标题层级 | 布局模型预测, **可能不准/不分级**(见 4.3 待验证) | 来自 Heading 样式/大纲级别, 最干净 | `#` 数量, 近乎无损 |
| 表格 | TableFormer 识别网格(含合并单元格) | 原生表格结构(含合并单元格) | **仅简单表格**: 源码里单元格一律 `row_span=1 / col_span=1`, 首行作 `column_header` |
| 图片 | 页面对象抽取, 需开 4.1 开关 | 内嵌媒体抽取 | 引用型(路径/URL), 无图片本体, `image_path` 记原引用 |
| `page_no` | `prov.page_no` 可靠 | 无页码概念 → `None` | → `None` |
| 首次运行 | 需下载 layout / TableFormer 模型 | 无 | 无 |

**`.doc` 坑**: docling 支持面里没有 `.doc`(1997 二进制格式, 无后端)。`parse.py` 对 `.doc` 后缀直接抛中文异常: "请先另存为 .docx(`soffice --headless --convert-to docx foo.doc` 或 Word 手动另存)"。**不做自动转换**——引入外部进程依赖不值当; 后缀与内容不符(改名冒充)会在后端深处报长堆栈, 入口校验 `path.suffix.lower()` 后给人话提示。

### 4.3 结构树 → `ParsedDoc` 的遍历骨架

```python
from docling_core.types.doc import DocItemLabel, ContentLayer   # 枚举拼写【待验证】

def walk(doc, doc_id: str, source: str) -> ParsedDoc:
    items, headings = [], []          # headings: [(level, title)] 标题栈
    for item, _lvl in doc.iterate_items():
        if getattr(item, "content_layer", None) == ContentLayer.FURNITURE:
            continue                  # 第一道: docling 判定的页眉/页脚/脚注
        page = item.prov[0].page_no if getattr(item, "prov", None) else None
        hp = " > ".join(t for _, t in headings)          # 非标题条目用它
        if item.label in (DocItemLabel.SECTION_HEADER, DocItemLabel.TITLE):
            lv = getattr(getattr(item, "heading", None), "level", 1)
            while headings and headings[-1][0] >= lv:
                headings.pop()                            # 回退到父级
            hp = " > ".join(t for _, t in headings)       # 弹栈后重算: 标题只含祖先, 别复用上面的 hp
            headings.append((lv, item.text))
            items.append(item_of("text", item.text, hp, page, level=lv))   # 标题自身成条目
        elif item.label == DocItemLabel.TABLE:
            items.append(item_of("table", item.export_to_markdown(doc), hp, page))
        elif item.label == DocItemLabel.PICTURE:
            items.append(item_of("image", "", hp, page, image_path=save(item, doc_id, page)))
        elif getattr(item, "text", None):
            items.append(item_of("text", item.text, hp, page))
    return ParsedDoc(doc_id=doc_id, source=source, items=items, meta={})
```

要点与坑:

- `iterate_items()` 按阅读顺序吐 `(item, level)`; **这里的 `level` 是结构树深度, 不是标题层级**, 别混用——标题层级是 `SectionHeaderItem.level` **直接字段**(2026-09-20 实测 docling 2.128.0: md `### ` → level=2, 即"# 数 − 1"); `TitleItem` 无 level(约定记 **0**)。
- **标题条目的 `heading_path` 必须在弹栈之后算**(先弹同级/更深的旧标题, 再拼面包屑): 复用弹栈前的值会把新章节挂到上一节下面——实测样例里"三、收尾"曾带上"二、图片", 而 模块 03的父块边界完全依赖这个值。
- **待验证**: PDF 的 `SECTION_HEADER` 是否携带可靠层级(布局模型可能全判 1), 以及空标题/过短标题的误判率。验证办法: 拿一份多级标题 PDF, 打印每个标题 item 的 `label / level / text` 看分布; 若层级不可用, 降级为"标题只做关键词载体, `heading_path` 退化为单级"并在 模块 03父块策略里写明(误判严重时在 parse 层加"过短标题丢弃"规则, 不在 模块 03修)。
- **待验证**: `TableItem.export_to_markdown(doc)` 的确切签名与 `DocItemLabel` / `ContentLayer` 枚举拼写。验证: `uv run python -c "from docling_core.types.doc import TableItem, DocItemLabel, ContentLayer; print([m for m in dir(TableItem) if 'export' in m]); print([l.name for l in DocItemLabel]); print([c.name for c in ContentLayer])"`。
- 遍历范围: 默认遍历的根通常是 `doc.body`, `doc.furniture`(页眉页脚)一般不出现——**两条路径都要兜住**(furniture 不出来靠 `content_layer` 判, 出来靠 4.6 规则判), 具体行为【待验证】: 打印 `doc.furniture.children` 与遍历结果的差集核对一次。

### 4.4 表格: 整表 Markdown 与合并单元格的坑

- 序列化用 `export_to_markdown(doc)`(或先 `export_to_dataframe()` 再 `to_markdown()`, 多一层 pandas 依赖, 不必); 失败兜底按 `item.data.grid` / `table_cells` 手拼(内部模型 `TableData.grid` 保留全部 span 元数据)。
- **合并单元格坑(官方文档核实的确定行为)**: Markdown 没有 rowspan/colspan 语法, 序列化器**只在起点格写值, 其余被覆盖的格子输出空**——即"摊平"。双层表头、斜表头等复杂表会出现整排空表头甚至行列观感错位; 检索仍可用(表头词还在文本里), 但**展示层不要依赖列对齐**。要保真时官方出口是 `export_to_html()` / `export_to_dict()`, 或自定义 `BaseTableSerializer`——首版不用, 记在这里备用。
- **单元格内换行/竖线坑(已实测, 不需要兜底)**: docling 2.128.0 的序列化器自己处理了——单元格内 `\n` 转空格、裸 `|` 转 `&#124;`(实测输出形如 `| 单元格 第二行 | 含&#124;竖线 |`)。所以 `clean.py` **不做** `<br>` / `\|` 替换(全量转义会把列分隔符一起毁掉), 只保留"表格 item 空白规整不破坏行结构"这条底线(非 `|` 开头的行并回上一行)。
- **跨页断表**: 一张表跨两页时 TableFormer 可能给出两个 `TableItem`。首版**不做自动拼接**, 靠 模块 03父块聚合(相邻 + 同 `heading_path`)把两张表放进同一父块, 检索上下文仍完整。
- **超长表格**: 整表不切后 `char_len` 可能远超父块目标 1200~1800; dense 侧截断策略交给 [./04-嵌入与Milvus索引.md](README.md)(多模态模型的文本上限 32,000 token, 截断仅作极端兜底, 具体以 模块 04为准; 模块 04对超大父块还有 VARCHAR 上限的前置检查), BM25 侧不受影响。
- 验收抽 3 张表核对行列数(§五); 调试期把 `doc.save_as_markdown()` 导出人读版对照, 是最省事的排查手段。

### 4.5 图片: 落盘 + 占位文本 + 开关

```text
RAG2_IMAGE_DIR(默认 data/rag2_images/)
└── <doc_id>/
    ├── p0001_i000.png     # 第 1 页第 1 张
    └── p0007_i000.png
```

- 按 `doc_id` 分目录: 重跑 ingest 直接整目录覆盖, 不残留旧图; 文件名零填充便于排序; `image_path` 记**相对 `RAG2_IMAGE_DIR`** 的路径(整目录搬迁不失效), 统一 PNG(`RAG2_IMAGE_FORMAT=png|jpg` 可切)。
- 占位文本模板: `[图片 <序号>: <image_path>; 图注: <caption 或 "无">]`——含路径与语义词, 保证 `text` 非空(稀疏路与评估文本上下文的最小可读信息), 图片块的语义主体则由 模块 04的多模态向量承担。caption 是独立条目, 与图片在阅读顺序里相邻(可能在前也可能在后), 取 ±1 条目窗口内同页的 caption。
- 取图 API: 官方示例用 `PictureItem.image`(PIL 图像, 依赖 `generate_picture_images=True`); 另存在 `get_image(doc)` 一类取图方法——**具体入口【待验证】**(用 4.3 的 `dir(TableItem)` 同款命令查 `PictureItem`)。
- 开关 `RAG2_IMAGE_DESC=off|vlm|ocr`, **默认 off**, 定位是**可选增强**(图片块已由 模块 04的多模态嵌入拿到真向量; 描述的作用是让图片可被 BM25/关键词命中、让评估文本上下文可读): `vlm` 走独立配置的 OpenAI 兼容端点(`RAG2_VLM_API_BASE/API_KEY/MODEL`, 与 judge 的 `RAG2_JUDGE_*` 分开; 模块 01变量表未收录, 开启时再补), `ocr` 只对图片区域跑本地 OCR。**代价**(开启前想清楚): 每图一次串行调用, 百图文档 ingest 时长 + 数分钟; VLM 描述进 `text` 后**解析结果不再确定**(同一文档两次 ingest 文本可能不同), 跑 [./06-ragas评估.md](README.md) 基线与新旧对比时必须冻结 `RAG2_IMAGE_DESC` / `RAG2_DO_OCR` 并在报告里注明。
- md 的引用型图片不搬文件、不联网抓取, 保持离线确定性。**实测修正(docling 2.128.0)**: md 后端**既不保留引用也不给图片本体**——`PictureItem.image` 恒为 `None`, `fetch_images` / `enable_local_fetch` / `enable_remote_fetch` 三种开关组合都试过, 都取不到 uri 或 PIL 图。所以这类条目 `image_path=None`、占位文本写 `[图片 n: 无本地图; 图注: ...]`, 检索只能靠占位文本 + 图注(图注在 md 里会另成一个普通 text 条目, 可被 BM25 命中); 要恢复引用得自己正则扫 md 源文本, 属 模块 02范围外的可选增强。

### 4.6 `clean.py`: 五条规则(逐项判定)

执行顺序: (1) 乱码/字符规整 → (2) 空白规整 → (3) 页眉页脚剔除 → (4) 重复元素去重 → (5) 超短行合并。**为什么这个顺序**: 归一化必须先做(否则重复比对与短行判定都不准); 剔除必须先于合并(否则页眉会被并进正文; 若先合并, 页眉已与正文焊接, 再也删不干净)。每步只做一类事, 单测逐规则覆盖。

**(1) 乱码/不可见字符清理**: 删 C0/C1 控制符(保留 `\n` `\t`)、零宽字符(`U+200B`、`U+FEFF`)、软连字符 `U+00AD`、私有区 `U+E000~U+F8FF`(嵌入字体图标); 正则删 `(cid:\d+)` 残留(PDF 字体未嵌入的经典乱码)。`U+FFFD` 替换符占比 > 1% → 整条 item 记 warning **不静默**(解码级问题, 清洗救不了, 该文档该走 OCR); 私用区占比 > 10% → 判定"字体映射失败"写入 `ParsedDoc.meta` 的 warnings。不做全半角标点强制统一(保留原文, 交给检索侧分词)。

**(2) 空白规整**: `\r\n`/`\r` → `\n`; 全角空格 `U+3000` 与不换行空格 `U+00A0` → 半角空格; 连续 ≥ 2 空格 → 1 个; 连续 ≥ 3 个 `\n` → `\n\n`; 每条 text 首尾 strip; 表格 item 内的换行按 4.4 转 `<br>`。**为什么必须做**: PDF 抽取常见"逐字空格 + 逐行换行", 不规整会让 模块 03子块的递归分隔符(段落 → 换行 → 中文句号)判断失准。

**(3) 页眉页脚剔除**(不依赖 bbox, 保持三格式通用):

- 规则 A(结构, parse 期已做): `content_layer == FURNITURE` 或 label 为 `page_header` / `page_footer` / `footnote` 的条目在解析阶段就不进 items(4.3)。
- 规则 B(跨页重复, clean 兜底): 判据全满足才剔——`type=text`、`level is None`(标题豁免)、归一化后长度 ≤ 50 字符、**出现在 ≥ max(3, 60% 页) 个不同 `page_no` 上**, 且该归一化键的全部出现**整组**剔除(只删命中的几页会留下残句)。归一化 = 去首尾空白 + 全角转半角 + 数字串替 `#`(吃掉页码)。典型命中: 逐页重复的公司名/文档编号/页码行/水印短句。页码全为 `None` 的 docx/md 不满足"不同页", 天然跳过, 符合预期。
- 规则 C(几何, 默认关): 需要 `prov.bbox`, 仅 pdf 有, 且"某页正文顶部恰好是标题"会误杀; 不实现, 只留 `RAG2_HF_GEOMETRIC` 开关位。
- 误伤风险与自查: 正文短句极少逐页原样重复, 风险低; 剔除条数记进 stats, 验收时抽查一份真实 pdf 的剔除清单。

**(4) 重复元素去重**: 相邻 ≤ 2 个条目内, 归一化(去空白与标点)后完全相等, 或 `difflib.SequenceMatcher(None, a, b).ratio() >= 0.95` 且长度 ≥ 20 → 保留先出现者(PDF 渲染抖动/双栏重排造成的重复条目)。跨页水印块是 (3) 的推广, 由规则 B 兜住。**保守阈值**: 目录与正文的同名标题天然相似但不相邻, 不受影响; 宁可少删——残留重复对检索的伤害小于误删正文。

**(5) 超短行合并**: PDF 布局模型常把每个视觉行切成独立 text item, 不合并则 模块 03子块会在行边界乱切。判据全满足才并: 前后相邻两个条目同为 `type=text`、`level is None`、`heading_path` 完全相同、后一个长度 < 30 字符 → 并入前一个; 拼接规则: 前一条目末字符是 ASCII 字母/数字则补一个空格(英文断行), 否则直接拼接(中文断行无空格)。长度 ≤ 4 的纯数字行(PDF 页码残片)单独出现时直接删。阈值可配(`RAG2_SHORT_LINE_MAX`, 默认 30)。**标题天然豁免**: 标题条目的 `level` 有值且 `heading_path` 不含自身, 不满足判据——这是 §三接缝约定 1 的回报。

```python
# clean.py 骨架(纯函数: 不 IO、不改原地、不跨条目移动内容)
def clean_document(doc: ParsedDoc, cfg) -> tuple[ParsedDoc, dict]:
    items = [_strip_invalid_chars(it) for it in doc.items]     # (1)
    items = [_normalize_ws(it) for it in items]                # (2)
    items, s1 = _drop_header_footer(items, cfg)                # (3) 规则 B
    items, s2 = _dedup_adjacent(items, cfg)                    # (4)
    items, s3 = _merge_short_lines(items, cfg)                 # (5)
    stats = {"dropped_hf": s1, "deduped": s2, "merged_short": s3}
    return replace(doc, items=items), stats
```
