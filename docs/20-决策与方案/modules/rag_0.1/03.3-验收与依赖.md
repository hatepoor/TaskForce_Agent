## 五、验收标准(自测清单)

实测口径(2026-09-21, **库版实现**): `tests/test_chunk.py` 21 项单测全绿(模块合计 42 项); 另跑两份语料 —— `data/rag2_samples/` 的 md/docx(各 9 条目, 短节密集)与一份 14,465 字符长 markdown(4 章 × 2 节, 每节 5 段正文 + 10 行表 + 一段 3000+ 字符无标题导言)。下表数字取自长文冒烟。

- [x] 父块达标率: 长文 **10/10** 个 text 父块落在 [1200, 1800](短节密集的 md/docx 样例 0/3, 属"宁小勿跨节"的豁免情形, 非缺陷);
- [x] 超长无标题正文触发退化切分: 产物父块最长 1778, 未超上限;
- [x] 表格父块整表不切: Markdown 行列完整(含表头分隔行), char_len=154 独立成块;
- [x] 表格父块的子块恰好 1 个且 chunk_type=table; 图片同理为单个 image 子块;
- [x] 子块 char_len ≤ 550(实测 max 496、中位 321; 目标 450 + 重叠 50); 相邻同父子块重叠实测 38 组全部落在 40~50;
- [x] 九字段全量携带且命名与全局定稿逐字一致(单测把字段名列表钉死); 父块 parent_id 为空; 每个子块的 parent_id 均能命中现存父块;
- [x] ID 合规: chunk_id / parent_id 符合 §2.4 规则, 同 doc 内序号单调无碰撞;
- [x] 确定性: 同一 ParsedDoc 切两遍, 输出完全一致(注入两个不同时钟比对, 冒烟里也复验了一次);
- [x] 单测(tests/, 无需 fake)覆盖: 中文句界样例(引号/小数/省略号)、空文档、纯表格文档、含图片文档、重复内容幂等(doc_id 相同)、跨页父块的子块页码、空壳标题块的三条边界;
- [x] **真实 pdf 的父块长度分布(2026-09-22 实测, 用 `data/pdf/补充.pdf`, 15 页数学讲义)**: 清洗后 156 条目 → **37 个父块**(中位 **84 字**, 最短 2, 最长 1703)、**49 个子块**(中位 116, 最长 500), 子块全部指向现存父块, 每父块子块数分布 `{1: 32, 2: 1, 3: 1, 4: 3}`。

  **结论(值得记住)**: 落在目标区间 `[1200, 1800]` 的只有 **1/37(3%)**, 没有任何父块超上限 —— 因为这份文档**节很短**(公式、短行多, 清洗阶段合并了 57 条超短行), 而规则 A 是"遇标题即闭合", 于是短节产出大量小父块。也就是说**「父块达标率」是文档形态的函数**: 模块 03 的样例长文是 10/10, 这份真 pdf 是 1/37, 两者都对 —— 小父块不会出错, 只是命中后回溯拿到的上下文更短。要不要在"节普遍很短"的语料上改成"跨节累积到目标字数"(规则 B 的一种加强), 属于**策略取舍**, 等 模块 06的评估能用量化证据回答(context_recall 是否因此受损)再定。

## 六、与其它模块的依赖关系

- **上游**: [./02-文档解析与噪声处理.md](README.md) 的 parse + clean 产出 `ParsedDoc`——doc_id、内容单元序列、标题栈快照、page_no、表格 Markdown、图片路径都在彼处落定, 本篇只消费;
- **下游**: [./04-嵌入与Milvus索引.md](README.md) 的 embed(子块文本 → 1024 维)与 store(children / parents 两 collection, 主键即本篇的 chunk_id / parent_id);
- **检索侧**: [./05-混合检索与RRF融合.md](README.md) 的父块回溯与按父去重, 直接依赖本篇的 parent_id 映射; 坑位一的 BM25 重复计分在彼处收口;
- **契约**: `ParentChunk` / `ChildChunk` 定义于 contracts.py, 归属与移植见 [./07-接口设计与移植方案.md](README.md);
- **横向**: 无——本篇不 import 本项目 agent/、tools/、settings/ 任何包, 不依赖 Milvus / LLM / docling(结构遍历已在 模块 02完成), 是全链路可移植性最强的一环。
