## 一、模块目标与边界

**目标**: 把 pdf / docx / md 三种文件统一解析成"结构化条目序列" `ParsedDoc`——每条带 `type`(text|table|image)、序列化文本、`heading_path` 标题面包屑、`page_no` 页码; 表格是整块 Markdown、图片落盘且有占位文本; 再清掉页眉页脚与文本噪声, 交给 模块 03做父子分块。

**边界(不做什么)**:

- 不切块([./03-父子分块策略.md](README.md))、不做 embedding 与入库([./04-嵌入与Milvus索引.md](README.md))、不做检索([./05-混合检索与RRF融合.md](README.md))、不做评估([./06-ragas评估.md](README.md));
- 不 import `agent/`、`tools/`、`settings/` 任何包; 全同步, 无 async/await; 配置只读 `RAG2_` 前缀;
- `.doc` / `.pptx` / `.html` 不在支持面: `.doc` 在入口直接报错并提示先转 `.docx`(不自动转换, 不引入 `soffice` 外部进程依赖);
- 图片语义描述与"扫描件全文 OCR"都是**可选开关, 默认关**——本模块不主动发起任何外部模型调用;
- 不做并发解析优化(全同步纪律): 大文件靠串行 + 进度日志, 见 4.7。

## 二、设计决策与理由(含备选对比)

### 2.1 三格式统一走 docling 的 `DocumentConverter`

| 备选 | 弃选理由 |
|---|---|
| pypdf / pdfplumber + python-docx + 自写 md 解析 | 三套数据模型要手工归一到"结构树"; pdf 天然没有标题层级、docx 天然没有页码, `heading_path` / `page_no` 只能靠正则猜; 表格靠启发式 |
| Unstructured | 结构标签粒度粗, 中文表格识别一般, 链路重 |
| Marker | 定位是"渲染成 Markdown", 拿不到可供切块决策的条目树 |
| **docling(选定)** | 一套 `DoclingDocument` 同时给出条目类型、标题层级、表格网格、图片、页码溯源(prov); PDF 侧布局模型 + TableFormer 质量在开源里第一梯队 |

收益与 模块 03直接相关: **父块边界依赖标题层级, chunk 元信息里的 `page_no` / `heading_path` / `chunk_type` 全部来自这里的解析结果**。代价(torch 级重依赖、首次下载模型、解析慢)在 [./01-环境与依赖.md](README.md) 已有预期管理, 接受。

### 2.2 保留结构树, 不"打平 Markdown 再正则切"

`doc.export_to_markdown()` 看着省事, 但打平后 label / level / prov 全丢, `heading_path` 与 `page_no` 只能猜。主路径是遍历结构树的 item 产出自有结构; Markdown 只用于**表格序列化**与调试导出(`doc.save_as_markdown()`), 不进主链路。

### 2.3 表格: 序列化为 Markdown + 整表原子

| 备选 | 弃选理由 |
|---|---|
| CSV | 表头与合并语义丢失, 逗号/换行转义脆 |
| HTML | 标签占字符, embedding 与 BM25 都在吃噪声 token |
| JSON / `export_to_dict()` | 保真最好, 但不可读、进不了 prompt, 行列与表头在检索时容易分家 |
| **Markdown(选定)** | 表头随身、LLM 读表最顺; 竖线行列文本经 jieba 分词后能被 BM25 以表头词精确命中 |

**整表一个 item、后续不切**(模块 03: 表格整块不切, 宁可超长): 表格从中间切开会毁掉行列结构, 每片都失去表头, 检索与生成双输。代价见 4.4。

### 2.4 图片: 落盘 + 占位文本, 描述生成默认关

图片块**不再只靠占位文本**参与检索: 图片落盘后其**文件路径会被 模块 04直接嵌入成真向量**(多模态 embedding `qwen3-vl-embedding`, 文本与图片映射同一向量空间), 图片块因此进 dense 路, 文本 query 可跨模态命中。占位文本仍写入 `text`(保证块非空, 稀疏路与文本展示不至于是无意义记录); `image_path` 进元信息, 随时可回溯原图。
`RAG2_IMAGE_DESC` 因此**降为可选增强**, 作用有二: 让图片块能被 BM25/关键词命中(占位文本只有路径与图注, 关键词面很窄), 让 模块 06评估的文本上下文可读。
代价(**开启前想清楚**): 每图一次 VLM/OCR 调用, 费用与 ingest 时长随图片数线性上涨; 单机本地系统也不该默认引入外部模型依赖(与本模块"不主动发起外部模型调用"的边界一致); 开关开启后重跑 ingest 就能补描述。

备选(不选): docling 自带 `do_picture_description` + `picture_description_options`(可挂 SmolVLM 之类的本地视觉模型, 官方示例存在)——无 API 成本, 但要多下一个视觉模型、Windows 上慢, 且把描述策略耦合进 converter 装配; 首版不做, 将来要加只是 4.1 里加三行。

### 2.5 噪声处理: parse 期白拿 furniture 判定, `clean.py` 用确定性规则兜底

docling 的 `DoclingDocument` 内建"正文 / 页眉页脚"区分——`body` 与 `furniture` 两棵根节点树(官方文档核实)。直接扔掉 furniture 下的 item 是零成本的; 但 docx/md 后端没有等价能力, 布局模型也会漏检, 所以 `clean.py` 自实现"跨页重复"兜底。分工: **parse 做白拿的、库版本相关的过滤; clean 做确定性、可单测、可解释的规则**——规则不随库版本漂移, 这也是 clean 能脱离 docling 单测的原因。

### 2.6 `doc_id` 内容寻址、`source` 相对路径(与 03/04 对齐)

- `doc_id = sha256(文件字节流).hexdigest()[:16]`, **解析阶段算好挂在 `ParsedDoc` 上**([03.1-目标与决策](./03.1-目标与决策.md) §2.4 定稿, 本篇透传): 同内容不同路径 → 同 `doc_id`, 重跑幂等; 内容变 → `doc_id` 变。
- 坑: 内容更新后旧 `doc_id` 的记录会残留 → 重灌时按 `source` 找出同源旧 `doc_id` 一并删除([./04-嵌入与Milvus索引.md](README.md) 的 `delete_doc` 支持)。这是内容寻址换幂等的代价, 明确记录, 不隐藏。
- `source` = **相对语料根的 POSIX 风格路径**(`Path(...).as_posix()`), 单文件入库时退化为文件名; 语料根由 `ingest.py` 编排层确定, parse 只负责转换。
