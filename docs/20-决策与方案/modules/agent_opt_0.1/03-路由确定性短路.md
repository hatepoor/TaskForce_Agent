## 一、目标

把 supervisor.md 里两条**纯确定性**的路由规则下沉为代码短路,命中时不再调用路由 LLM:

- **汇总轮短路**(原规则 5 的唤醒轮场景):派发完成后的自动汇总轮(合成通知触发)必然选 answer,现在却每次烧一次路由 LLM;
- **URL 短路**(原规则 12):用户消息含 URL 必须派 research,LLM 没有裁量权,判断本身是字符串操作。

其余路由(含用户轮带回收结果的场景)仍走 LLM——用户在同轮里既看到结果又提新要求时,LLM 的裁量是必要的,不短路。

## 二、改动:`supervisor.py` route_node

在 plan 推进块之后、`load_prompt("supervisor")` 之前插入:

```python
    # ---- 确定性短路(P2):命中即跳过路由 LLM,规则出处见 prompts/supervisor.md 历史版 ----
    last = state["messages"][-1] if state["messages"] else None
    lastText = str(getattr(last, "content", "") or "")
    isWakeRound = lastText.startswith(PREFIX_SYSTEM_NOTICE)
    if injected and isWakeRound:
        # 唤醒轮 + 有回收结果:必然汇总作答(原规则 5 代码化),用户轮不短路(用户可能提了新要求)
        return Command(goto="answer", update={**plan_extra, "subagent_results": injected})
    if (
        not state.get("plan")
        and not injected
        and ("http://" in lastText or "https://" in lastText)
    ):
        # 用户消息带 URL:必然派 research(原规则 12 代码化);plan 执行中/汇总轮让位于
        # 既有语义,已接受"URL + 其他意图"需用户下轮补充说明的代价
        route = Route(
            next="dispatch",
            tasks=[Task(agent="research", task=lastText, reason="用户消息含 URL,抓取正文")],
        )
        jobs = [(t.agent, build_contract(t, state)) for t in route.tasks]
        task_ids = tasks.submit(jobs, thread_id=thread_id or "") if tasks is not None else []
        if not task_ids:  # 无管理器(单测/备胎):回退既有 LLM 路由
            pass
        else:
            detail = "、".join(f"{a}:{tid}" for (a, _), tid in zip(jobs, task_ids, strict=False))
            return Command(
                goto=END,
                update={
                    "last_route": route.model_dump(),
                    "messages": [AIMessage(
                        content=f"已派发 {len(task_ids)} 个后台任务:[{detail}]。"
                        "完成后我会自动汇总,期间你可以继续聊别的。"
                    )],
                },
            )
```

要点:

- `Task`/`Route` 已在 supervisor.py import 清单里,无需新 import;
- 派发确认文案与既有 dispatch 分支**同款**(双入口体验一致);`tasks=None` 备胎路径回退 LLM 路由,Send 备胎不支持的场景不扩;
- `task=lastText`:URL 类用户消息本身就是自包含任务(链接 + 要求),`build_contract` 会带上 user_utterance;
- `update` 不带 `plan_extra` 之外的键——短路分支不触碰 plan 状态(已用 `not state.get("plan")` 闸住)。
