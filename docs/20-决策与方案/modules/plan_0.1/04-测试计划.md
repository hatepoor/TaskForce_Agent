# plan_0.1 · 04-测试计划

> 测试由智能体负责编写维护(项目纪律);fake 内联,不依赖真实 LLM/DB/沙箱。

## 1. fake 模式约定

- fake structured LLM 参照 `tests/test_graph.py` 的 `FakeStructuredLLM`:`with_structured_output(schema, **kwargs)` 返回自身、`invoke` 返回预设值;plan 测试需**断言 `method="function_calling"` 被透传**(防 DeepSeek 400 静默兜底回归,supervisor.py:94-97 同款坑)。
- interrupt 往返参照 `tests/test_ask.py`:`graph.stream` 捕获 `__interrupt__` → `Command(resume=...)` 恢复。
- 派发单测用 `FakeTaskManager`(`submit` 记录 jobs、返回固定 id 序列 `["t1","t2",...]`),不起真线程;端到端用真 `TaskManager` + stub 子图(`agent/subagents/stub.py` 先例)。

## 3. 验收标准

1. `uv run ruff check .` 干净(line-length 100)。
2. `uv run pytest -q` 全绿:基线 **429 passed** + 新增约 20 条,零失败(外部依赖 skip 不阻塞)。
3. CLI 冒烟(你执行,.env 就绪):`uv run python -m cli.repl` → 输入「对比宁德时代和比亚迪 2024 年的毛利率并给出投资建议」。预期:路由 plan → 计划快照 → interrupt 确认(输入 y)→ 首批派发 → watcher 唤醒自动推进 → 收口汇总;全程快照勾选变化可见。
4. HITL 恢复冒烟:计划确认挂起后退出进程 → `/resume` → 输入 y 恢复执行(验证 checkpointer 挂起态含 plan 字段,联动 01 §5 白名单验证)。

## 4. 重点盯防用例

- **_run 正常路径 task_id 回填**(test_run_backfills_task_id):若子图 finalize 未填,推进对账整体失效——这是全链路最脆的一环。
- **唤醒轮前缀判定**:`PREFIX_SYSTEM_NOTICE` 前缀的历史回填消息不会进入 route_node 实时消费路径(service.py 注释),测试覆盖一条防回归。
- **recursion_limit**:5 步全链 13 轮 + 用户插话,模块 10 已放宽至 40,冒烟时观察是否逼近。
