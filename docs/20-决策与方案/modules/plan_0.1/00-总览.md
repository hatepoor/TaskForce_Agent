# plan_0.1 · 00-总览

> 一页纸总览:目标、范围、设计决策、里程碑状态、文档索引。
> 架构决策的完整推理见 `docs/20-决策与方案/adr/0012-plan-and-execute.md`。

## 1. 目标

给 TaskForce(企业级投资调研助手)加上 **Plan-and-Execute** 能力:

用户提出复杂问题(如"对比宁德时代与比亚迪 2024 年的毛利率并给出投资建议")→
supervisor 识别为需拆分 → planner 生成 todolist(≤5 步)→ **用户确认(HITL)** →
按依赖关系分批派发给三个子智能体 → 每批完成后自动推进下一批 → 全部完成后收口汇总。

## 2. 范围边界

**做**:plan 路由分支、计划生成、HITL 计划确认、依赖解锁与分批派发、失败级联跳过、收口汇总、REPL 进度快照(嵌在消息文本,零新机制)。

**不做**(遗留项,见 TODO.md):API 侧 plan 事件帧(前端轮询已有,够用)、失败步自动重试/replan、计划编辑(本期只允许 确认/取消)、同步 Send 备胎通道支持 plan(无 TaskManager 场景退化为 answer)。

## 3. 设计决策(摘要,详见 ADR-0012)

1. **计划生成用 LLM,计划推进用确定性代码**——推进逻辑是 supervisor 里的纯 Python 短路,不走 LLM 路由,可靠且可测。
2. **HITL 拆双节点** `plan_draft → plan_confirm`——interrupt 重入时 plan_confirm 重跑无副作用,不重复调 LLM;挂起点仍在主图(ADR-0008 节点清单修订为 ask/memory/plan_confirm)。
3. **step 对账零契约变更**——ResultSummary 已有 `task_id`(summary.py:22),派发时把 submit 返回的 task_id 回填 PlanStep,回收后按 task_id 匹配;summary.py 一行不改。
4. **plan 存 dict**——AgentState.plan 存 model_dump(同 last_route 先例,state.py:27,避免 msgpack 自定义类型告警)。
5. **复用双通道与自动唤醒**——派发走 TaskManager.submit;推进由 REPL watcher(AUTO_NOTICE 唤醒轮)与 API 前端轮询(/chat/summary)驱动,两端无新机制。
