## 一、问题定义

### 1.1 现状

主图两处把 checkpoint 里的全量 messages **直塞** LLM,无任何裁剪:

- `src/agent/supervisor.py` route_node(约 L137-140):
  `messages = [SystemMessage(content=system), *state["messages"]]`
- `src/agent/answer.py` answer_node(L146):
  `messages = [SystemMessage(content=system), *state["messages"]]`

PostgresSaver 全量存储本身**正确且不动**——它的职责是无损持久化(HITL 挂起恢复、断线续聊、时点回放),全量快照是根基。真正的问题是:**存储层与视图层是同一个东西**,"checkpoint 里存什么"和"每轮发给 LLM 什么"没有分离。

### 1.2 后果

- 长会话 token 线性上涨,最终超窗。
- 子图侧已有 16k 字符预算闸门(`subagents/react.py` `CONTEXT_BUDGET_CHARS`),主图裸奔。
- 现状 prefix cache 是命中的(messages append-only,见 §2.3),但命中的是全量前缀——总量依然失控。

### 1.3 目标与硬约束

- **目标**:主图发给 LLM 的上下文有界,长会话可持续。
- **硬约束**:prefix cache 命中率不降(DeepSeek 缓存命中部分价差约 10 倍,命中率下滑会吞掉裁剪收益)。
- **不动**:checkpoint 语义、子图私有键机制、前端历史回填行为。

## 二、方案定稿

### 2.1 三层结构

| 层 | 载体 | 更新频率 | 是否事实源 |
|---|---|---|---|
| 存储层 | `state["messages"]`(add_messages reducer) | append-only,每轮 | **唯一事实源**,永不删改 |
| 派生层 | `AgentState.contextDigest: dict` = `{"digest": str, "uptoId": str}` | 仅 compact 时 | 否,可从存储层重建 |
| 视图层 | `assembleView(...)` 每轮现算的输出 | 每轮 | 否,不落 state |

- `digest`:水位之前全部历史(含旧 digest 增量)的结构化摘要文本。
- `uptoId`:水位 = digest 已覆盖到的**最后一条消息的 id**(用 id 不用条数,理由见 §六.3)。
- 水位之后的原始消息即"活跃段"。

### 2.2 拼装公式

```
发给 LLM 的消息序列 =
    [SystemMessage(固定 system)]                      # 进程级稳定(ADR-0011 现状)
  + [SystemMessage(digest)]                           # 仅当水位 > 0;冻结期内逐字节不变
  + [水位之后的原始消息(逐条确定性截断)]              # append-only,绝不裁剪、绝不滑动
```

两处消费点共用同一拼装函数:

- `supervisor.py` route_node:**只消费**(digest 已存在就用),不触发 compact;
- `answer.py` answer_node:消费 + 是**唯一** compact 触发与写回点。

### 2.3 缓存友好性论证(为什么"每轮现算"不破缓存)

前缀缓存按请求**逐 token 从头匹配**:本轮与上轮请求开头连续一致的部分才命中。

1. **现状命中的根源**是 messages append-only:本轮请求 = 上轮请求的全部内容 + 尾部新增,前缀完全重合。
2. 拼装是**确定性纯函数**。三个输入稳定——digest 冻结(compact 之间不动)、水位不动、messages append-only——则每轮输出**字节级等于**上轮输出 + 尾部新增。"现算"与"缓存 miss"没有必然关系,缓存命中与现在完全一致,零损失。
3. **compact 触发轮**:digest 变更 + 水位前跳,该轮请求除固定 system 外全 miss——一次性的、低频的(活跃段再次涨满预算才下一次),可接受。
4. **否决滑动窗口**:窗口起点每轮前移(丢最老、加最新),除固定 system 外每轮全 miss;裁剪省下的 token 远抵不过失去的缓存折扣。这正是 Claude Code 选择 compaction 而非滑窗的原因,本项目同样否决。
5. **否决一切非确定性视图**:任何"同样输入每轮可能产出不同文本"的视图层逻辑(动态重摘、随机截断)都直接破坏前缀稳定。

### 2.4 compact 机制

- **触发点**:`answer_node` 入口,确定性检查 `overBudget`(活跃段字符数 > `context_budget_chars`,纯字符数算法,与 `react.py` 的 `_msgs_overBudget` 同风格)。不在 supervisor 触发——路由每轮必跑,热路径不加重活。
- **动作**:调一次摘要 LLM(复用 answer 的生成侧实例),把「旧 digest + 水位后消息」增量摘要为新 digest;提示词为 `src/prompts/compact.md`(`$digest` / `$transcript` / `$target` 槽位,`string.Template` 纪律)。
- **写回**:answer 节点返回值带 `{"contextDigest": {"digest": 新文, "uptoId": 本批最后一条消息 id}}`,`contextDigest` 为**单点写**(仅 answer;supervisor 只读)。
- **降级**:摘要调用异常 → 保留旧 digest 与水位继续服务(超预算轮不阻塞对话),打日志。
- **阈值提前量**:预算线取上下文窗口的约 60-70% 即触发,压缩后新请求越小,单次 miss 代价越小;摘要调用本身是独立请求,不影响主对话请求序列的缓存。

### 2.5 超长单条消息:确定性截断

用户粘贴超长文本、webfetch 结果内嵌等场景,单条消息超 `long_msg_limit` 时在**视图层**截断为固定长度 + 固定省略标记(`…[截断,原文 N 字符]`)。

- 缓存安全:确定性函数 × 不变输入 = 每轮截出逐字节相同的文本,前缀稳定不破。
- 不改写 checkpoint 里的原文(存储层红线)。

### 2.6 与 Claude Code 的同构对照

| Claude Code | 本项目 |
|---|---|
| transcript JSONL(全量落盘,只增不删) | `state["messages"]` + PostgresSaver checkpoint |
| compaction 摘要(写进上下文,不删 transcript) | `contextDigest.digest` |
| 摘要后从水位继续 | `uptoId` 水位 |

本项目比它更有利的一点:**任务进度不在消息里**——plan 是独立结构化键(`AgentState.plan`)、TaskManager 账本对账、`subagent_results` 消费即清。摘要只需管对话层(用户偏好、已确认口径),任务进度有结构化兜底,摘要丢细节不影响执行正确性。

## 三、状态与契约变更

- `src/agent/state.py` 的 `AgentState` 新增键:`contextDigest: dict`。
  - 结构:`{"digest": str, "uptoId": str}`;未 compact 过为空语义,读写一律 `state.get("contextDigest") or {}`(兼容无该键的旧 checkpoint)。
  - 序列化:纯 dict + str,msgpack 无忧(先例:`last_route` 存 dict 的既有注释)。
  - 归属:AgentState 本就定义于 `agent/state.py`,不涉及 `agent/contracts/` Pydantic 契约;属共享 state 变更,已在 ROADMAP §7 登记(2026-10-03)。
- **子图隔离**:`SubgraphState` 不声明同名键,`contextDigest` 不会泄漏进子图(子图本就不读主图 messages,红线同 `react_msgs` 私有键纪律)。

## 六、红线(实施时逐条对照)

1. **`state["messages"]` 永不删改**——checkpoint 全量层是唯一事实源,任何"清理历史"的诱惑都否决。
2. **digest 绝不写入 messages channel**——一旦混入,add_messages 把它永久焊进历史,水位与前端回填全乱;digest 只存在于独立 state 键与拼装结果。
3. **水位用 message id 对齐,不用条数**——条数在任何中途插入/重排场景下错位;id 由 LangChain 生成且稳定。
4. **摘要调用不进 supervisor 热路径**——路由每轮必跑,compact 只在 answer。
5. **子图机制不动**——`react_msgs` 私有键与 16k 闸门保持原样;`contextDigest` 不被子图 state 声明同名。

## 七、坑位预判(实施中验证,验证后按纪律先问再沉淀 troubleshooting)

- **uptoId 定位失败**(旧会话消息被外部清理等):降级为水位 0 → 全量直塞(即现状行为),打告警日志,不抛错。
- **旧 checkpoint 无 `contextDigest` 键**:`state.get()` 默认空 dict,自然兼容。
- **摘要 LLM 与 thinking 模式**:摘要非交互路径,`LLM_THINKING=enabled` 时慢一点可接受;若实测过慢,复用 routeLlm 的 disabled 实例(实施时定,不预设)。
- **`string.Template` 转义**:digest/transcript 作为 slot **值**传入不受 `$` 影响;`compact.md` 模板正文里如需字面 `$` 用 `$$`。
- **与 P2 的相邻改动**:P2 动 route_node 的 plan 短路逻辑(约 L127-135),本模块动 L137-140 拼装行——同函数不同区域,实施顺序已定 P0→P1→P2→本模块,誊写时注意两批改动不互缠。
- **`_MESSAGE_WARN_THRESHOLD = 40`**(service.py):现有告警阈值按全量 messages 计,本模块不改它;活跃段超预算由 compact 管线负责,两套阈值语义不同勿混。
