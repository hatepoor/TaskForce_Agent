## 0. 设计原则与后端契约速查

### 0.1 三条设计原则

1. **工具,不是产品**。没有引导页、没有 mascot、没有庆祝动画、没有空状态插画。界面存在的意义是让"智能体正在干什么"和"我还能管什么"这两件事一眼可见。
2. **信息密度优先于留白**。单用户工具不需要靠大间距撑气场。对话正文 14px/1.7,外壳 13px,元信息 12px,角标 11px。
3. **状态靠克制的方式表达**。用一条 12px 的字、一个 6px 的圆点、一条 2px 的左边框区分状态;**不用色块、不用徽章海洋、不做位移动画**。整个界面只有一个强调色。

### 0.2 后端契约速查

**SSE 事件格式**:每帧 `data: {"<类型>": <载荷>}\n\n`,**单键对象,无 `event:` 行**,前端按键名分发。JSON 为 `ensure_ascii=False`(中文直出)。字段级契约以 API-CONTRACT.md 为唯一事实源,此处仅列 UI 相关要点:

| SSE 事件 | 负载要点 | 前端动作 |
|---|---|---|
| `token` | 增量字符串 | 追加到当前轮正文末尾(字符串累加,非 replace) |
| `route` | `{next, question, tasks[]}`,`next ∈ answer\|ask\|memory\|dispatch` | 轨迹条累加一条记录 |
| `interrupt` | **对象信封** `{kind: "ask"\|"memory"\|"unknown", text}`(B3 后) | 按 kind 判别卡片类型并挂起输入 |
| `usage` | `{thread_id, calls, input_tokens, output_tokens}`,**进程级累计** | 差分后展示本轮增量角标 |
| `error` | `{message, code?}`(B4 后) | 错误条;`code: "recursion_limit"` 按正常回复样式呈现 |

**关键事实**:① B4 前**没有 `done` / `error` 帧**,读流结束即本轮结束,`completed` vs `broken` 靠客户端判定;② `route` 只含路由决策,**不含子智能体 ResultSummary**;③ `usage` 是进程累计值;④ `POST /chat` 需带 body,**不能用 `EventSource`**,须 `fetch` + `ReadableStream` 手工解析。

**子智能体身份色**(轨迹/摘要里唯一允许出现的彩色):

| agent | 中文名 | 色(深色模式) |
|---|---|---|
| `retriever` | 知识库检索 | 蓝 `#5b9dff` |
| `research` | 联网调研 | 紫 `#a98bff` |
| `executor` | 沙箱执行 | 琥珀 `#e0a552` |

- 当前项:图标着 `--accent` + `--accent-soft` 淡底,左侧 2px 竖条指示;每项**常驻文字标签**(v1.3 起,10px;原先只有悬停 tooltip,四个图标认不全)。顶部一个品牌标记(与 AI 头像同语义的三点连线)。
- 切视图**不卸载 ChatView**:`<KeepAlive>` 保住对话状态与滚动位置,SSE 进行中切走再切回不丢流。

- **不做的**:面包屑、页签、全局搜索、命令面板、主题切换按钮(主题跟随系统 `prefers-color-scheme`)。

## 3. 对话流交互细节(重点)

### 3.1 轮次结构

一个"轮次"(Turn)从用户发送开始,到流结束为止。**挂起不结束轮次**——用户回答后同一轮次继续追加内容。轮次内从上到下固定顺序:

```
用户消息 → 路由轨迹条 → 子任务批次卡 → AI 正文 → 用量角标
```

轮次之间用 24px 空白分隔,**不画分隔线**。每个轮次是独立的数据对象,流式增量只影响最后一个未闭合轮次。

### 3.2 消息气泡类型

**用户消息**——右对齐,`--bg-raised` 底,6px 圆角,max-width 80%,`white-space: pre-wrap`。不加头像,不加"你"标签。

**AI 回复**——左对齐,**不用气泡**,直接铺在背景上(气泡会限制 markdown 排版)。限宽 760px。流式追加时末字符位置一个 1px 宽闪烁竖条光标;**流式期间渲染纯文本**(`pre-wrap`),结束后才走 Markdown(半截语法渲染不出正确结果,顺便省性能,见 ARCHITECTURE 坑 5)。结束后光标消失,正文下方 12px 处出现元信息行:`2 次调用 · 入 3.2k / 出 412 tok`。

> **2026-09-18 补(用户要求)**:AI 正文左侧加 26px 中性图标头像(`AiAvatar.vue`,三点连线语义),与正文顶端对齐;头像本身不抢强调色,仅在"思考中"时描边转为 `--accent` 并轻微呼吸。

**路由轨迹条**——本轮所有 `route` 事件**聚合成一条**,默认一行摘要,可点开:

```
收起态:
  ● 派发 · retriever + research  2 项并行 ▸

展开态:
  ▾ 路由轨迹 (3 步)
    ① 派发 2 项
       ● retriever  检索本地知识库中 pgvector 的部署方式
         理由:问题涉及本地文档
       ● research   联网查 FAISS 的运维成本与社区活跃度
         理由:需要最新外部信息
    ② 汇总作答
```

`next` 到中文映射:`answer→汇总作答`、`ask→需要补充信息`、`memory→记忆写入`、`dispatch→派发 N 项`。流进行中圆点轻微呼吸(2s 周期透明度 1→0.4),流结束变实心静止。**这是整个界面唯一的动画。**(2026-09-18 补:随 AI 头像一并加入"思考中三点跳动 + 头像呼吸",见 §3.2 AI 回复注;动效仍限于这三种状态指示,无装饰性动画。)

**子任务批次卡**——一次 `dispatch` 生成一张卡:

```
进行中:
  ┌─────────────────────────────────────────────────────┐
  │ 派发 2 个子任务                                       │
  │ ● retriever  检索本地知识库中 pgvector 的部署方式      │
  │ ● research   联网查 FAISS 的运维成本与社区活跃度       │
  └─────────────────────────────────────────────────────┘
```

**注意(异步派发架构的硬约束,2026-09-18 更新)**:后端是"异步派发"——supervisor 提交任务立即返回"已派发"确认并结束本轮,子任务结果在**下一轮** `drain_done()` 时才回灌。因此 SSE 流内等不到"已完成"信号;原计划靠批次卡示意,现改为**前端轮询 + 自动汇总**(`useTaskWatch` 3s 探 `GET /chat/tasks`,全批完成自动发起 `POST /chat/summary`):派发确认与汇总正文都直接落在对话流里,**不再有批次卡**。语义与 REPL 一致(用户轮优先,流式期间不抢跑)。

**用量角标**——AI 正文下方 12px 灰字,**不做卡片、进度条、颜色**。由于 `usage` 事件是进程累计值,前端做差显示本轮值;右侧抽屉 UsagePanel 展示进程累计值,标签写清("本轮" / "进程累计")。

### 3.3 interrupt 挂起卡

判别规则(B3 信封):按 `interrupt.kind` 分派——`ask` → 问询卡,`memory` → 确认卡,`unknown` → 禁用输入 + "检测到未知类型的挂起" + 新开会话出口。挂起期间 `Composer` 置灰禁用,提示"请先回答上方问题"。

**ask 问询卡**:

```
  ┃ 需要补充信息
  ┃ ┌───────────────────────────────────────────────────────┐
  ┃ │ 请问要检索的知识库范围是?你希望覆盖哪几份文档?          │
  ┃ │                                                       │
  ┃ │ ┌───────────────────────────────────────────────────┐ │
  ┃ │ │ 输入你的回答…                                      │ │
  ┃ │ └───────────────────────────────────────────────────┘ │
  ┃ │ Enter 发送 · Shift+Enter 换行                          │
  ┃ └───────────────────────────────────────────────────────┘
  ┃  2px 左边框,用 --accent
```

- 卡片出现时**输入框自动聚焦**并强制滚入视野(`scrollIntoView({block:'nearest'})`,即使用户正在上滚)。
- 发送 → `POST /chat/answer`,卡片**立即原地折叠**为已解决态,新流追加到同一轮次。
- 返回 400(挂起已在别处恢复):卡片标失效,提示"该挂起已失效",触发会话状态刷新。

**memory 确认卡**:

```
  ┃ 记忆写入确认
  ┃ ┌───────────────────────────────────────────────────────┐
  ┃ │ 将写入长期记忆(仅存于你本地的 pgvector):              │
  ┃ │ ┌───────────────────────────────────────────────────┐ │
  ┃ │ │ 用户偏好用 uv 管理 Python 依赖,不用 pip。          │ │  ← proposal 原文
  ┃ │ └───────────────────────────────────────────────────┘ │
  ┃ │ 来源:本轮对话自动提案        [ 忽略 ]  [ 记入记忆 ]    │  ← 主按钮 accent
  ┃ └───────────────────────────────────────────────────────┘
```

- 提案文本引用块样式(左 2px 竖线 + `--bg-input` 底)。
- 主按钮 accent;次按钮 ghost;**默认焦点在"忽略"**,回车不误触写入。
- 两按钮都走 `POST /chat/confirm`(true/false),返回 SSE。
- **已解决态**(两种卡共用),折叠为一行,保留在历史里:

```
  ✓ 已补充回答 · "只看 docs/ 下那几份"                    14:22
  ⊘ 未记入长期记忆                                         14:22
```

### 3.4 空态 / 加载态 / 错误态

**空态**(无会话或新会话首屏):居中 520px 宽区域,一行标题 + 一行说明 + 三个示例问句按钮(点击**填入** Composer,不直接发送):

```
                        本地 Agent 工作台

     可以问我:本地知识库里的文档、需要联网查的最新资料、需要跑起来验证的代码。

     ┌────────────────────────────────────────────────────┐
     │ 总结一下 docs/ 里关于记忆设计的那部分                │  ← 点击填入输入框
     │  知识库检索                                        │
     ├────────────────────────────────────────────────────┤
     │ 查一下 pgvector 0.7 的 HNSW 参数默认值,给出建议      │
     │  联网调研 + 知识库检索                              │
     ├────────────────────────────────────────────────────┤
     │ 写段脚本统计 docs/ 下每个 md 的字数                  │
     │  沙箱执行                                          │
     └────────────────────────────────────────────────────┘
```

**加载态**:用户发送后**立刻**插入用户气泡与一条空的 AI 正文占位(只有一个闪烁光标),**不做骨架屏**。若 800ms 内无任何事件到达,光标上方补一行 12px 灰字"正在路由…";**首轮冷启动**(惰性装配图 + MCP 可能几十秒)1s 内给"正在初始化智能体…"反馈,防止用户重复点击。

**错误态**:分三类,处理方式不同。

| 情形 | 表现 | 可做的操作 |
|---|---|---|
| 请求未发出/HTTP 非 2xx | 错误条:`连接失败:502 · 服务是否在运行?` | 重试(重发同一请求) |
| 流中途断开(已有部分 token) | 正文保留,下方接错误条:`连接中断,以上内容可能不完整` | 复制已生成内容 / 重试 |
| B4 后 `error` 帧 `code: "recursion_limit"` | 正常正文样式:`本轮任务循环过深,已中止。请把需求拆小一点再试。` | 无(它就是一条正常回复) |

```
  ┌──────────────────────────────────────────────────────┐
  │ !  连接中断,以上内容可能不完整                          │
  │    [ 重试 ]  [ 复制已生成内容 ]                         │  ← 边框 --danger,底色透明
  └──────────────────────────────────────────────────────┘
```

**关于"重新生成"——明确不做。** 后端挂 checkpointer,重发同样文本会产生第二条重复用户消息污染上下文;真正的重新生成需要"回退 checkpoint 重跑"接口,当前不存在。首版只提供**重试**(仅限请求失败或零输出情形),流中断时提供**复制**让用户自己重发。宁可少一个按钮,不做一个语义错误的按钮。

### 3.5 流式与滚动

fetch + `response.body.getReader()` 手工解析(POST 不能用 EventSource)。解析器按 `\n\n` 切帧(先归一化 CRLF),`data: ` 前缀后 `JSON.parse`,单键分发。**token 追加用 16ms rAF 节流批量写入**(非响应式缓冲拼接后一次性赋值,见 ARCHITECTURE 坑 5)。

## 5. 视觉方向与设计 Token

### 5.1 基调

**深色为默认,浅色跟随系统备选。** 理由:这是长时间盯着的本地工具,深色降低视觉疲劳;深色下"低亮度分层"比浅色更容易做得克制——近黑底 + 微弱亮度差分层,极少分隔线撑起结构。

- **分层靠亮度,不靠边框**。四级背景 `base → panel → raised → hover`,每级亮度差 4–6%。边框只在表格、输入框等真正需要时出现,对比度极低。
- **只有一个强调色**:冷蓝 `#5b9dff`。只出现在四处:当前导航项、主按钮、焦点环、链接。**其余一律无色。**
- **身份色只给三个子智能体**:8px 圆点 + 12px 标签文字,不做色块背景。这是唯一多色区域,承载真实信息。
- **语义色只在真出问题时用**:成功绿几乎不出现(大部分"成功"用灰字表达),警告黄、危险红只在错误条与删除按钮。
- **圆角小**:4/6/8px。开发者工具的"认真感"来自紧凑和对齐,不是大圆角卡片。
- **动效几乎为零**:hover 过渡(120ms)+ 轨迹点呼吸态,**仅此两处**。没有消息飞入、没有列表错峰淡入、没有骨架屏闪光。`prefers-reduced-motion` 下全部关闭。

**"像认真做的开发者工具"的三个具体判据**:① 等宽字体用在所有 id、路径、命令、用量数字;② 表格悬停整行高亮、数字列右对齐;③ 焦点环清晰可见(2px outline offset 1px),键盘可达。

| `Ctrl/Cmd + N` | 全局 | 新建会话并聚焦输入框 |
| `↑` | Composer 且**为空**时 | 取回上一条发送过的用户文本(仅本地历史,最多 20 条) |

**中文输入法的坑(必须处理)**:`Enter` 发送判断必须维护显式组合态标志——只判 `event.isComposing === false` 在部分输入法下不可靠:

```
compositionstart → isComposing = true
compositionend   → isComposing = false(并忽略紧随其后那一次 keydown)
keydown Enter    → if (isComposing || e.isComposing) return;  否则发送
```

漏了这步,中文用户选词按回车会误发送半截拼音——中文项目最高频的交互事故。

### 6.2 滚动到底策略

MessageList 维护 `isPinnedToBottom`,"贴底"定义为 `scrollHeight - scrollTop - clientHeight <= 48`。

1. **默认贴底**。新轮次开始(用户发送)时无条件滚到底并置 `isPinnedToBottom = true`。
2. **流式输出期间**,每个 token 批次追加后**仅当贴底为真**才自动滚底;为假时**完全不动**——用户上滚看历史时内容绝不跳动。
3. **用户滚动监听**:任何 scroll 事件后重算贴底状态。向上滚超阈值 → false;滚回底部 → 自动恢复 true。被动监听 + 不去抖,用当前值短路,避免自动滚动引起的事件回环。
4. **暂停期间显示回底提示**:列表右下角浮出 48×32 胶囊 `↓ 新内容`,点击回底。流结束后仍在,直到用户回底或发下一条。
5. **挂起卡出现时强制滚入视野一次**。
6. **切换会话**:恢复该会话上次滚动位置,无记录则到底。
7. **不做**滚动锚定补偿。若 markdown 渲染抖动明显,给代码块和表格预设 `contain-intrinsic-size`,不引滚动锚定库。

### 6.3 其他细节

- 代码块:右上角悬停"复制"按钮;超 20 行默认折叠为 12 行 + "展开"。
- 长链接自动断行(`overflow-wrap: anywhere`),不撑破 760px 栏宽。
- 所有 id(doc_id、thread_id、记忆 key)等宽字体 + 点击复制 + 1.5s `已复制` 内联反馈。
- 空列表一律一行灰字说明 + 一个可执行的下一步动作,不放插画。
- 全局禁用文本选区仅限导航轨图标与按钮;正文、id、错误信息**必须可选中**。

## 7. 与后端的接口缺口(裁决结果)

核对接线发现的硬约束,已并入全量设计 README 的改造三批次(B1~B8),此处登记对应关系与前端侧约定:

### 7.1 SSE 非真流式 → 后端 B4(第一/二批交界,随 M3 做)

`_sse_run.gen()` 攒完全部帧再 yield,首字节延迟 = 整轮耗时,打字机/光标/轨迹逐条出现全部失效。**裁决:B4 用 `queue.Queue` + worker 线程真流式(不违反全同步红线)+ `error` 事件帧**,随 M3 一起落地。落地前 UI 按"可能一次性到达大批帧"设计(加载态先上、rAF 合并),解析器零改动。

### 7.2 子任务结果推送 → **2026-09-18 已落地(改为轮询 + 自动汇总)**

原设想"dispatch 完成后补发 `result` 事件"在**异步派发架构**下不成立:任务提交后本轮已 END,结果下一轮 `drain_done()` 回灌。按当初登记的方向实现:后端补非消费 peek 端点 `GET /chat/tasks?thread_id=` + 自动汇总端点 `POST /chat/summary`(以 `AUTO_NOTICE` 跑一轮,与 REPL watcher 同语义);前端 `useTaskWatch` 3s 轮询(页面隐藏/视图失活暂停),`pending === 0 && done > 0` 且无流式轮次时自动发起汇总——**用户无需再问一句**。批次卡(SubagentBatchCard)取消。

### 7.3 会话列表无元数据 → 后端 B2 + 前端本地标题

裁决:后端 `GET /chat/threads/meta` 纯 SQL 提供排序/活跃度;标题由前端取首条输入截 20 字存 localStorage(换浏览器丢标题,可接受)。"删除会话"无后端端点,**首版不做**(只提供本地清除视图,弹窗明示"仅清除本地展示,服务端上下文保留")。

### 7.4 上传单文件 → 前端串行,后端不改

多选拆串行 N 个请求,本地单用户场景足够,不为多文件改后端签名。

### 7.5 usage 进程累计 → 前端差分,后端不改

相邻快照差分显示本轮增量;刷新后首轮快照丢失差值偏大,可接受。
